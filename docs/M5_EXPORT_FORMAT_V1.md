# M5 — format JSON de groupe, version 1

`OurFinanceGroupExport` est un **format intermédiaire de données de groupe**, téléchargeable depuis la PR #54 mais sans restauration activée. `serializeGroupExportV1` ne sérialise que les champs déclarés et refuse un instantané incohérent : identifiants dupliqués, membres absents des opérations, paiements ou parts ne totalisant pas le montant exact, impacts historiques déséquilibrés, reçu sans dépense associée. Les montants sont des entiers sûrs en unités mineures, séparés par devise ; aucune conversion n'est inférée.

Le validateur refuse aussi les payeurs/parts dupliqués ou négatifs, les états de catégories ou reçus inconnus et les booléens de suppression mal formés. Une dépense supprimée ne peut pas porter un reçu encore `active` dans l'archive : ses métadonnées doivent être marquées `deleted` avant l'export. Cela permet de conserver la trace du reçu sans promettre un fichier privé que le Worker refuse de lire.

Le document contient le groupe, ses membres, dépenses (paiements, allocations et instantané de catégorie effectivement persistés), règlements dans une seule devise, opérations importées `undetermined`, catégories personnalisées (identifiant d'icône et couleur) et métadonnées des reçus. Chaque reçu porte `mediaIncluded: false` : le JSON ne contient **aucun octet de reçu**. Il ne constitue donc ni une sauvegarde complète ni une preuve de restauration. Les préférences personnelles, invitations, commentaires, événements d'audit, remboursements interdevises et paramètres du compte ne sont pas encore représentés. L'export de chaque octet privé doit passer par un accès autorisé au Worker, produire une empreinte et être testé séparément avec révocation et restauration fictives.

Prochaines étapes : lire toutes les pages Firestore sous les règles du groupe, fournir un instantané cohérent malgré les écritures concurrentes, construire le fichier à partir de ces données, ajouter les collections encore absentes, télécharger les médias privés avec manifeste d'intégrité, puis vérifier une restauration de test. Sur Firebase Spark, aucun export/import géré Firestore n'est activé. Ne pas traiter ce format comme un export final de production.
