# Services métier et vérification V1

La description fonctionnelle des pages est [PAGES_SITE_DESIGN.md](PAGES_SITE_DESIGN.md). Une page peut assembler plusieurs domaines : les droits et transactions sensibles restent dans le Worker ; les services Angular appellent le Worker ou lisent Firestore sous Security Rules. Un service métier n'a pas besoin de contenir toute une page ni d'être une classe unique.

## Seuil CI

`PR validation` et `Validate stacked PR SHA` exécutent `npm run test:coverage`. Depuis #226, le seuil bloquant est **90 % de lignes, 90 % de branches et 90 % de fonctions** sur le périmètre Node explicite des services métier Angular, utilitaires partagés et Worker. La fusion simulée de #222 sur `main` `a15b686` a passé 435 tests et mesuré 96,96 % lignes, 90,32 % branches et 95,45 % fonctions ; la CI du squash `53c0586` est [verte](https://github.com/ranouf/OurFinance/actions/runs/44381767941). Le détail du périmètre et les limites figurent dans [M6_COVERAGE.md](M6_COVERAGE.md). Un seuil global ne prouve pas chaque fonction : la dernière colonne ci-dessus reste à fermer avec des essais ciblés par page. Les composants/templates Angular et les parcours navigateur ne sont pas couverts par cette mesure Node.

Les PR de page doivent relier chaque fonction ajoutée aux tests unitaires, aux règles et à l'essai intégré nécessaire, puis indiquer le SHA exact et les limites. Une PR UI qui ajoute un service client conserve ses tests sur cette même page ; les PR backend ajoutent les tests des transactions et des droits correspondants.
