# M5 — import et photos : état au 18 novembre 2026

Le parseur CSV Splitwise natif et le variant historique exact conservent les impacts nets et la précision d'origine sans inventer de payeurs ou de conversion. Le Worker valide les lots déjà préparés, l'anti-doublon et l'annulation ; les exports JSON/CSV et ZIP V2 préservent les chaînes exactes. Les essais fictifs [#127](https://github.com/ranouf/OurFinance/pull/127) et [#144](https://github.com/ranouf/OurFinance/issues/30#issuecomment-6967293793) ont couvert import préparé valide, doublon, annulation, rapprochement, export et restauration. L'écran d'import n'appelle pas encore le parseur du rapport officiel : ce raccordement est suivi dans [#183](https://github.com/ranouf/OurFinance/issues/183).

Les reçus Cloudinary `authenticated` sont servis via le Worker après vérification du groupe ; propriétaire/membre 200, tiers/révoqué 403 et URL non signée 401 ont été observés sur TEST. La sauvegarde/restauration V2 a été éprouvée avec 30 PNG fictifs, puis les reprises d'uploads orphelins ont été ajoutées par [#153](https://github.com/ranouf/OurFinance/pull/153). Un ZIP V2 synthétique de 18 761 771 octets a obtenu un aperçu 200 ; la limite de 20 000 001 octets donne 413 sans écriture. L'[essai TEST #149](https://github.com/ranouf/OurFinance/issues/149#issuecomment-6971322044) a observé suppression de dépense 204 avant upload 502 compensé, sans métadonnée, journal ni asset résiduel. L'ordre inverse, la vraie interférence au commit Firestore, les pannes fournisseurs globales et le déclencheur UI après fermeture d'onglet restent ouverts dans [#149](https://github.com/ranouf/OurFinance/issues/149).

L'aide Chrome Manifest V3 aux exports officiels Splitwise n'est pas implémentée : son bénéfice et ses permissions minimales sont suivis dans [#173](https://github.com/ranouf/OurFinance/issues/173). Le format de sauvegarde `group-v2-partial` n'exporte pas les comptes Firebase Auth. Le critère M5 complet reste ouvert jusqu'au raccordement UI final et aux validations restantes.
