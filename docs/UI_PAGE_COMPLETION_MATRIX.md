# Matrice de complétude fonctionnelle des pages V1

État au 18 novembre 2026, sur `main` (`f29dbaa`) et les PR ouvertes à cette date. Cette matrice suit la **fonctionnalité** ; la refonte graphique du PR #137 reste un chantier distinct. « Présent » signifie que le code existe, pas que le parcours intégré est validé.

## Méthode et règle de clôture

Trois passages indépendants ont été effectués :

1. **Exigences** : `PLAN_TECHNIQUE_V1.md`, `PAGES_SITE_DESIGN.md`, `DESIGN_EVERYDAY_POP.md`, `INVITATIONS_QR.md`, `M6_READINESS.md` et les protocoles M0–M6. Les sections sans route dédiée restent dans leur page parente.
2. **Implémentation** : routes, `app-pages.ts`, composants `features`, services `core/firebase`, Worker et PR ouvertes, en distinguant `main` des branches en brouillon.
3. **Preuves** : tests unitaires et règles, CI au SHA exact, commentaires d'essais locaux/TEST et limites de `M6_READINESS.md`. Les constats contredisant une ancienne documentation sont classés selon le code et la preuve les plus récents. Un service testé seul ne valide pas sa page.

Une page est **complète fonctionnellement** lorsque tous ses états utiles sont accessibles depuis l'interface, reliés aux services réels, vérifiés avec données fictives sur desktop et mobile, en FR/EN/JA, avec droits membre/tiers/révoqué selon le cas ; le PR a une revue sans commentaire ouvert et le workflow « PR validation » vert sur son HEAD. Les captures et vidéos d'un PR UI sont dans sa description, jamais dans le dépôt. La validation visuelle du propriétaire précède fusion et déploiement UI. Réserver TEST dans l'issue #30, puis retirer les variables temporaires et nettoyer les fixtures avant de libérer la pile.
