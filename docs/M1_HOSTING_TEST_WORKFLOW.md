# M1 — déploiement manuel de Hosting de test

Le workflow `test-hosting-deploy.yml` ne s’exécute que par `workflow_dispatch`, cible uniquement le projet `ourfinance-test` et déploie uniquement **Hosting**. Il ne publie pas les règles Firestore, les index ni le Worker et ne cible jamais la production. Il construit `public/app-config.json` depuis les identifiants Web du projet de test ; ce fichier est ignoré par Git. L’API key Web Firebase est nécessairement distribuée au navigateur et ne doit pas être assimilée à une clé de service.

Avant toute exécution, créer hors dépôt une identité de déploiement dédiée à Hosting **sur `ourfinance-test` seulement**, avec les permissions minimales vérifiées par un essai, puis enregistrer sa clé JSON comme secret Actions `TEST_FIREBASE_DEPLOY_SA_JSON` (de préférence limité à l’environnement GitHub `test`). Ne jamais utiliser `FIREBASE_SERVICE_ACCOUNT_JSON` du Worker : ce compte a seulement le rôle Datastore User et sa clé ne doit pas être copiée dans GitHub. Vérifier aussi que les variables Actions `TEST_FIREBASE_PROJECT_ID`, `TEST_FIREBASE_APP_ID`, `TEST_FIREBASE_AUTH_DOMAIN` et le secret Web `TEST_FIREBASE_API_KEY` sont présents. Le workflow refuse tout autre ID/domaine de projet.

**État : workflow préparé, non exécuté.** Cet environnement ne peut pas lire la liste des secrets Actions (HTTP 403) ; la présence de `TEST_FIREBASE_DEPLOY_SA_JSON` reste à confirmer par un administrateur, sans afficher sa valeur. GitHub n’expose `workflow_dispatch` que pour un workflow présent sur la branche par défaut : son premier essai Actions attend donc une revue et une intégration autorisée du fichier, avec le secret de test confirmé. Après configuration, lancer manuellement le workflow depuis une branche de test révisée, contrôler les journaux sans secret, ouvrir le site de test sur ordinateur et mobile, puis consigner le SHA et les résultats dans l’issue #30. Ne pas déclencher ce workflow pendant un créneau de pile réservé à un autre essai. Les previews par PR, le déploiement contrôlé des règles/index/Worker et la production restent séparément à faire.
