## Interface Everyday Pop

Les huit maquettes et `docs/ui-kit/README.md` font référence. `#124` (Connexion, Dashboard, shell), `#128` (Groupes, Profil), `#131` (Dépenses), `#132` (Statistiques) et `#137` (galerie/composants) restent des tranches UI soumises à validation visuelle. Leurs captures Playwright desktop/mobile et vidéos réelles doivent être dans chaque description de PR, hors dépôt, au SHA exact ; une fixture locale en mémoire ne prouve pas un déploiement TEST. La PR UI des noms des membres `#135` a été fermée automatiquement après suppression de la branche API parente `#134` ; la tâche locale réempile son code sur `#124`. Aucun de ces écrans n'est déclaré conforme sur `main` à ce stade.

## TEST et critères de sortie

Les réservations et nettoyages de `ourfinance-api-dev`/`ourfinance-test` sont consignés dans l'[issue #30](https://github.com/ranouf/OurFinance/issues/30). Les essais utilisent des fixtures fictives et retirent les flags POC après chaque créneau. `#139` est fusionné sur `main` au commit `04d5219` après le retest exact au SHA `ecf6200` et le nettoyage documenté dans le [commentaire TEST](https://github.com/ranouf/OurFinance/issues/30#issuecomment-6960785360). La preview CSP de `#121` n'a pas remplacé le site TEST principal. Le workflow Worker `#141` reste en brouillon jusqu'à la confirmation des accès TEST ; son premier lancement réel devra être vérifié après publication du workflow sur `main`.

`#144` est fusionné sur `main` au commit `d71661b` après deux essais TEST sur le HEAD exact `7f86c1f` : deux groupes CAD/JPY, import valide et annulé, sauvegarde/aperçu/restauration V2, refus tiers/révoqué et nettoyage complet ([résultat final](https://github.com/ranouf/OurFinance/issues/30#issuecomment-6967293793)). `#146` reste en brouillon : un essai de sa liaison de limitation 120/60 s a observé neuf réponses 429, mais leur corps et `Retry-After` n'ont pas été capturés ; un retest unique s'est arrêté sur une erreur réseau du client ([résultat](https://github.com/ranouf/OurFinance/issues/30#issuecomment-6967557257)). L'activation V1 a été retirée après chaque essai et aucune donnée n'a été créée pour cette limite.

Avant la V1 : valider visuellement les écrans finaux, intégrer les piles compatibles, rejouer M1–M6 sur les SHA intégrés exacts, prouver les refus intergroupes et les reprises de restauration, tester Android/iOS, lecteur d'écran, performances et quotas Free, puis vérifier les workflows de déploiement TEST. La production exige une décision séparée du propriétaire.
